# hunt-telegram-collector

Небольшой CLI-сборщик вакансий из явно выбранных Telegram-каналов и групп.
Python 3.11+, Telethon 1.45.0, SQLite, YAML. Работает вручную на macOS и по расписанию
на Linux. Использует **пользовательскую сессию Telegram**, не Bot API.

Сообщения сохраняются независимо от фильтра; окончательную оценку выполняет человек
или отдельная задача ChatGPT. Нет LLM, платного API модели, веб-сервера или Docker.

## Установка

```sh
git clone https://github.com/melixetian/hunt-telegram-collector.git
cd hunt-telegram-collector
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -c constraints.txt -e .
cp .env.example .env
cp config.example.yaml config.yaml
chmod 600 .env
hunt --help
```

Прямые зависимости зафиксированы в `pyproject.toml`; `constraints.txt` фиксирует
также транзитивные зависимости и дополнительные пакеты для тестов/Sheets.
Базовая установка не устанавливает Google-пакеты.

## Telegram: API-реквизиты и вход

1. Откройте [my.telegram.org](https://my.telegram.org), войдите в свой аккаунт и
   выберите **API development tools**. Создайте приложение и получите `api_id`/`api_hash`.
2. Заполните **локальный** `.env` через редактор:

   ```dotenv
   TELEGRAM_API_ID=ваш_числовой_id
   TELEGRAM_API_HASH=ваш_api_hash
   HUNT_DATA_DIR=
   GOOGLE_APPLICATION_CREDENTIALS=
   ```

3. Запустите в своём терминале:

   ```sh
   hunt login
   ```

Номер, код входа и пароль 2FA вводятся скрыто и не сохраняются в конфигурации/логах.
Не отправляйте их в чат. `collect` никогда не начинает интерактивный вход.
Повторный `login` использует уже существующую сессию.

По умолчанию данные находятся в `~/.local/share/hunt-telegram-collector/`:

- `telegram.session` — секретная пользовательская сессия;
- `messages.sqlite3` и файлы WAL/SHM — сообщения, курсоры и состояние экспорта;
- `collector.lock` — блокировка одновременных запусков;
- `exports/messages.jsonl` — снимок всех накопленных сообщений.

`HUNT_DATA_DIR` меняет каталог. Используйте постоянный абсолютный путь **вне исходников**.
CLI создаёт новые файлы с правами только для владельца (`umask 077`). Не размещайте
данные в публичной папке, Git или общедоступной облачной синхронизации.

**Сессия даёт доступ к Telegram-аккаунту.** Allowlist источников ограничивается кодом
приложения, а не правами самой сессии. При компрометации завершите эту сессию через
Telegram → Настройки → Устройства. `.gitignore` исключает `.env`, локальную конфигурацию,
сессии, SQLite, JSONL и стандартные имена файлов credentials; произвольно названный
секретный файл всё равно нужно хранить вне репозитория.

## Источники и темы

```sh
hunt sources
hunt sources --topics -1001234567890
# либо
hunt sources --topics @forum_username
```

`sources` показывает названия, username, помеченные отрицательные ID групп/каналов и
признак форума. API списка диалогов может включать последнее сообщение диалога в
ответ; сборщик его не сохраняет и не выводит. Личные диалоги не выводятся.
Числовые ID копируйте из команды целиком, включая `-100…`; положительные raw ID
намеренно не принимаются. При необходимости access hash ищется среди доступных диалогов.

В `config.yaml` явно включите нужные источники, например:

```yaml
collection:
  initial_days: 7
  refresh_days: 2
  page_size: 100
  retries: 3
  max_flood_wait: 60
  request_timeout: 45
  page_pause: 1

sources:
  - peer: '@vacancy_cs'
    kind: jobs
  - peer: '@hrlunapark'
    kind: jobs
  - peer: '@zarubezhom_jobs'
    kind: jobs
  # - peer: -1001234567890
  #   kind: general
  #   topics: [123, 456]
```

Три username — примеры; доступность и содержимое не гарантированы.
В поставляемом `config.example.yaml` источники выключены.

Если `topics` отсутствует или пуст, читается вся группа. При заданных темах каждая
имеет собственный курсор, сохраняются только сообщения этих тем. Новая тема получает
свой первый семидневный обход. `1` — тема General: для неё Telegram не предоставляет
отдельную историю replies, поэтому читается история выбранной группы, а сообщения
остальных тем отбрасываются до сохранения. Для прочих тем запрашивается их thread.
Корневая сервисная запись создания темы не входит в историю replies.

Сборщик не вступает в сообщества, не отправляет сообщения, не ставит реакции,
не откликается на вакансии и не вызывает API отметки истории прочитанной.
Недоступный источник попадёт в отчёт об ошибках; остальные будут обработаны.

## Первый сбор и просмотр

```sh
hunt collect
hunt status
hunt export
```

`status` показывает количество сообщений, распределение фильтра, курсоры, незавершённые
обходы и последние запуски сбора/экспорта. В отчёте время — `Europe/Moscow`, в SQLite
и экспорте — ISO 8601 UTC. Команды возвращают `0` при успехе, `1` при ошибке (включая
ошибку отдельного источника), `2` при неверной конфигурации и `130` при Ctrl-C.

Для просмотра экспортированного текста локально:

```sh
python - <<'PY'
import json
from pathlib import Path
path = Path.home() / '.local/share/hunt-telegram-collector/exports/messages.jsonl'
for line in path.open():
    row = json.loads(line)
    if row['filter_result'] != 'noise':
        print(row['record_key'], row['filter_result'], row['message_url'])
        print(row['text'][:800], '\n')
PY
```

При нестандартном `HUNT_DATA_DIR` замените путь. Повторите `collect` и `export`:
количество строк без новых сообщений не увеличится. Проверьте несколько ссылок и
исходных текстов, прежде чем подключать последующую задачу ChatGPT.

Сразу после установки без реквизитов уже работают `status` и `export`; пустой экспорт
не означает, что соединение с Telegram проверено. Нужен хотя бы один успешный реальный
`collect` с сообщениями. Секреты не нужны для автоматических тестов.

## Хранение и восстановление

Уникальность: `(chat_id, message_id)`, ключ экспорта: `chat_id:message_id`.
Хранятся название/username/ID источника, ID сообщения/темы, дата публикации и правки,
время наблюдения версии (`collected_at`), оригинальный текст/подпись, ссылки, признак
медиа, результат/причина фильтра. Повторное наблюдение неизменённой версии не меняет
`collected_at`, поэтому экспорт стабилен. При правке обновляются исходные поля.
Скрытые URL Telegram entities извлекаются с учётом UTF-16 offsets.

История читается страницами от новых сообщений к старым. Страница и позиция обхода
сохраняются одной транзакцией. Незавершённый обход сохраняет исходную временную
границу и продолжается после перезапуска; основной курсор продвигается после его
завершения. Новые сообщения, пришедшие в процессе обхода, заберёт следующий запуск.
Последующий сбор дочитывает всё после курсора, даже после долгого простоя, и повторно
проверяет сообщения, опубликованные за последние `refresh_days`.

FloodWait до `max_flood_wait` ожидается, сетевые/серверные ошибки повторяются с
ограниченной задержкой; число повторов ограничено `retries`. Более долгий FloodWait
оставляет источник на следующий запуск. Таймаут одной операции — `request_timeout`.
Ошибки выводятся по типу, без тел ответов API и содержимого запросов. Например:
`ChannelPrivateError` — проверьте доступ вручную; `UsernameNotOccupiedError` — username;
`FloodWaitError` — повторите позже; `ConnectionError`/`TimeoutError` — соединение.

Все команды используют один `flock` на каталог данных (macOS/Linux). После завершения
процесса ОС освобождает блокировку; файл блокировки удалять не нужно. Используйте
**один экземпляр приложения и один каталог данных** для одной сессии и одного назначения.
SQLite и блокировка рассчитаны на локальный диск, не NFS.

## Предварительный фильтр

- `jobs`: широкий охват — любой текст остаётся кандидатом, сомнения помечаются `review`.
- `general`: признаки вакансии **и** профессии дают `candidate`; один из двух — `review`.
- «Ищу работу» / резюме — `review`, а не удаление; конфликт сигналов тоже `review`.
- Медиа без текста — `review / media_without_text`.
- Нет сигналов — `noise`; это сообщение всё равно сохраняется и экспортируется.

Русские/английские regex-массивы в `filters` заменяют соответствующие значения
по умолчанию; варианты внутри списка объединяются через OR. Нет требований к
зарплате, визе, стране или релокации. Репосты с идентичным текстом из другого чата
помечаются `probable_duplicate_of`, но остаются отдельными записями с оригинальными
ссылками. Это указатель на возможный повтор, не команда удаления.

Ссылки закрытых supergroup/channel имеют `link_access=members_only`: открыть их могут
только участники с доступом. Для basic groups ссылка отсутствует. URL публичного
источника не гарантирует, что конкретное сообщение ещё доступно.

## JSONL

```sh
hunt export --format jsonl
hunt export --output /absolute/path/incoming.jsonl
```

Экспортирует **все** накопленные строки, включая `noise`. Это полный снимок с одной
строкой на ключ, не append-журнал. Временный файл синхронизируется и атомарно заменяет
предыдущий; после этого отдельно подтверждается состояние экспорта в SQLite.
Правки попадут в следующую версию снимка. Удаление источника из конфигурации прекращает
новый сбор, но не удаляет историю и не исключает её из экспорта.

## Необязательный Google Sheets

Без Google credentials сбор и JSONL полностью независимы от Google.
Реальное назначение нужно согласовать отдельно. Приложение не создаёт таблицы/листы
самостоятельно и **отказывается писать в любой лист с названием «Вакансии»**.
ID личной основной таблицы не включён в код или примеры.

1. Создайте отдельную входящую таблицу и пустой лист, например `Telegram Inbox`.
   Отдельная таблица предпочтительна: Google выдаёт доступ сервисному аккаунту ко всей
   таблице, а не только к одному листу.
2. В своём проекте Google Cloud включите **Google Sheets API**. Создайте отдельный
   service account. Не выдавайте ему project-wide Editor/Owner и domain-wide delegation.
3. Создайте JSON key и сохраните **вне репозитория**, например
   `~/.config/hunt-telegram-collector/service-account.json`, с правами `600`.
4. Поделитесь **только входящей таблицей** с email сервисного аккаунта, роль Editor.
   Не давайте ему доступ к основной таблице, если выбран отдельный входящий документ.
5. Установите дополнительный набор и задайте путь в локальном `.env`:

   ```sh
   python -m pip install -c constraints.txt -e '.[sheets]'
   ```

   ```dotenv
   GOOGLE_APPLICATION_CREDENTIALS=/absolute/path/service-account.json
   ```

6. Задайте в `config.yaml`:

   ```yaml
   sheets:
     spreadsheet_id: 'ID_СОГЛАСОВАННОЙ_ВХОДЯЩЕЙ_ТАБЛИЦЫ'
     worksheet: 'Telegram Inbox'
   ```

7. Выполните `hunt export --format sheets`, затем повторите и убедитесь, что строки
   не продублировались. Проверьте обновление правки и сохранение полей обработки.

Подключение Google Drive в ChatGPT **не предоставляет credentials этому приложению**.
Используется OAuth scope Sheets; доступ к документам задаётся sharing выбранного
сервисного аккаунта. Drive API не нужен.

Сборщик владеет столбцами **A:Q** и их заголовками:

```text
record_key, chat_id, source_title, source_username, message_id, topic_id,
published_at, edited_at, collected_at, text, message_url, link_access,
links, has_media, filter_result, filter_reason, probable_duplicate_of
```

Пустому листу добавляются заголовки; несовпадающая схема или повторные ключи останавливают
запись. Поля ChatGPT (`processing_status`, `notes`, `main_record_id` и др.) добавляйте
**начиная с R** — сборщик их не пишет. Не переставляйте A:Q и не меняйте `record_key`.
Текст записывается в режиме `RAW`, поэтому формулы из Telegram не исполняются.

Перед экспортом читаются реальные ключи и значения. Обновляются существующие строки,
новые получают конкретные номера строк; слепой `append` не используется. После потери
ответа или локального подтверждения следующий проход повторно читает ключи, поэтому
уже записанные строки не вставляются снова. Запись идёт пакетами до 100 строк;
при необходимости увеличивается размер существующего листа. Текст не обрезается:
поле свыше лимита ячейки вызывает ошибку, полный текст остаётся в JSONL/SQLite.

Google Sheets не даёт транзакцию «прочитать ключи + условно вставить». Поэтому один
пишущий экземпляр — обязательное условие; не запускайте ещё один сборщик с другой
машины/каталога на тот же лист. Во время экспорта не сортируйте физически строки,
не вставляйте и не удаляйте их; используйте filter views. После экспорта ChatGPT
читает входящие строки и отдельно переносит подходящие в основной лист «Вакансии»,
проверяя дубли. Этот проект не меняет статусы откликов и не реализует такой перенос.

## Linux и периодический запуск

Установите Python 3.11+ с venv и базу часовых поясов (`tzdata`), клонируйте проект,
создайте venv и повторите установку. Войдите в Telegram на Linux интерактивно либо
перенесите сессию, `.env` и каталог данных по защищённому каналу при остановленном
сборщике. Для переноса состояния копируйте весь каталог данных после завершения
процессов; не копируйте активную SQLite отдельно от WAL. Не используйте одну сессию
одновременно на двух машинах.

Пример cron для пользователя `collector` (пути замените на свои):

```cron
17 * * * * cd /home/collector/hunt-telegram-collector && .venv/bin/hunt collect >> /home/collector/hunt.log 2>&1
27 * * * * cd /home/collector/hunt-telegram-collector && .venv/bin/hunt export >> /home/collector/hunt.log 2>&1
```

Отдельный экспорт выгрузит уже сохранённые сообщения даже после ошибки одного
источника. Если сбор ещё работает, блокировка отклонит экспорт; следующий запуск
повторит его. Для Sheets замените вторую команду на `hunt export --format sheets`.
Общие опции идут **до** подкоманды, например:

```sh
/path/to/.venv/bin/hunt --env-file /secure/.env --config /secure/config.yaml collect
```

Cron здесь только пример; установка проекта не создаёт расписание сама.

## Проверки разработки

```sh
python -m pip install -c constraints.txt -e '.[dev,sheets]'
pytest -q
ruff check src tests
ruff format --check src tests
python -m pip check
```

Тесты используют fake Telegram/Sheets без реальных запросов. Покрывают пагинацию,
транзакционность страницы, восстановление незавершённого сбора с исходной границей,
долгий простой, ошибки источников, FloodWait, правки, фильтр, темы, UTF-16 URL,
межканальные дубли, блокировку, JSONL и неопределённый результат записи в Sheets.
CI проверяет Python 3.11/3.13 на Linux. Успешные unit-тесты не подтверждают доступ
к реальному Telegram-аккаунту или реальной таблице.

## Ограничения первой версии

- Нет OCR, скачивания медиа, восстановления/удаления записей удалённых сообщений.
- Правки сообщений, **опубликованных** раньше окна перепроверки, автоматически не
  обнаруживаются. Увеличьте `refresh_days` до нужной глубины; это увеличит число запросов.
- Смена regex применяется к сообщениям при следующем наблюдении в окне перепроверки;
  старые записи не переклассифицируются автоматически.
- Правила фильтра эвристические. Удалённый/закрытый/переименованный источник требует
  ручного исправления конфигурации; миграция basic group в supergroup — новый ID.
- Изменение настроек времени не меняет уже начатый незавершённый обход.
- JSONL и Sheets формируют снимок в памяти; рассчитано на небольшую личную коллекцию.
- `sources`/перечень тем — интерактивные команды; при сетевой ошибке их можно повторить.
  Политика ограниченных повторов применяется к подключению и операциям `collect`,
  а также к временным ошибкам экспорта Sheets.
- Нет проверки заявленных работодателем условий, автоматических откликов и обработки
  входящих строк ChatGPT внутри сборщика.
